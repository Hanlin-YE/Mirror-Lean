# Mirror · 镜身 — 技术实现文档（TDD）

**配套文档**：《Mirror · 镜身 — 产品文档（PRD）》
**目标硬件**：Unitree G1（23 / 29 DoF 人形）
**机器人接口**：unitree_sdk2（C++，CycloneDDS 总线）
**文档状态**：v1.1（v1.0 基于调研笔记成文；v1.1 完成开源组件线上核实，选型由「待验证」升级为「已确认」，并新增 8.2 人力排期）

## 1. 系统总览

### 1.1 目标

实现「第三人称躯体复刻（Mistake Mirroring）+ 动态姿态演变（Motion Morphing）」的完整技术管道，支撑 PRD 定义的四步主循环（观察 → 成为你 → 对比 → 修正），并优先保障 Hackathon 60 秒 Demo 的稳定呈现。

### 1.2 非目标（v1）

- 不做实时全身遥操作（复刻为**录制后回放**，非实时闭环）；
- 不做双足步态行走（演示动作为**原地上肢 + 微下蹲**类动作，降低摔倒风险）；
- 不做自研全身 RL 控制器（复用重定向 + 轨迹回放方案）。

### 1.3 架构分层

```
┌─────────────────────────────────────────────────────────┐
│  Experience Orchestrator（体验状态机 + 屏幕UI + 语音）      │
├─────────────────────────────────────────────────────────┤
│  Scoring & Progress      Motion Morphing   Diff Engine   │
│  （评分与进步曲线）         （A→B 轨迹渐变）   （差异量化）    │
├─────────────────────────────────────────────────────────┤
│  Motion Store（标准轨迹库 B / 用户轨迹 A / 会话档案）        │
├─────────────────────────────────────────────────────────┤
│  Retargeting Engine（SMPL 人体 → G1 29 DoF 关节轨迹）      │
├─────────────────────────────────────────────────────────┤
│  Capture Service（单目/RGB-D → SMPL 参数流 + 3D 骨骼）     │
├─────────────────────────────────────────────────────────┤
│  unitree_sdk2（低层接口 LowCmd 关节级下发，CycloneDDS）     │
└─────────────────────────────────────────────────────────┘
```

### 1.4 端到端数据流（Demo 管道）

```
[相机捕获用户动作 A]
   ↓ 30–60fps
[3D 骨骼提取（SMPL）] ── 记录轨迹 A
   ↓
[Retargeting：SMPL → G1 关节角] ── 校验（碰撞/限位/稳定）
   ↓
[Diff Engine：A vs 标准轨迹 B] ── 差异高亮 + 量化分
   ↓
阶段1：G1 复刻动作 A（用户第三人称回看自己的错误）
阶段2：G1 从 A 渐变插值至修正姿态 B（Motion Morphing）
阶段3：用户二次尝试 → 重合度上升曲线（闭环完成）
```

## 2. 技术栈与选型

**开源组件验证状态：2026-08-27 已全部完成线上核实，无一虚构，选型成立。**

| 层 | 首选 | 备选 | 状态（2026-08-27 核实） |
| --- | --- | --- | --- |
| 人体捕获 + 重定向（一体化） | **NVlabs/GEM-X**（单目视频 → SOMA 77 关节全身姿态 → 直接 retarget G1） | WHAM（yohanshin/WHAM，世界坐标 3D 人体）+ soma-retargeter 两段式 | ✅ 均真实存在；GEM-X Apache-2.0，含 ONNX/TensorRT 加速 demo |
| 人体→G1 重定向 | NVIDIA soma-retargeter（github.com/NVIDIA/soma-retargeter，BVH → G1 29 DoF CSV，Newton/Warp GPU IK） | humanoid-dexart-retarget（真实，但定位是铰接物体灵巧操作，不对口，不选）；自研比例归一 + IK | ✅ Apache-2.0；v0.1.0（2026-03）；需 NVIDIA GPU（Maxwell+）、Python 3.12、git LFS |
| 差异对比 | 自研生物力学特征引擎（PoseForge 已开源可参考：github.com/DataVisards/PoseForge） | CoachMe（arXiv 2509.11698，参考式教练指令生成，偏语言反馈） | ✅ PoseForge 开源（React+Three.js 前端 + FastAPI 后端）；CoachMe 为论文 + 项目页 motionxperts.github.io，非开源库 |
| 轨迹渐变 | Spacetime 约束插值 / 缓动插值 + 安全校验 | 线性插值 + 限幅 | 自研 |
| 机器人控制 | unitree_sdk2（C++ 低层接口） | unitree_sdk2_python（快速验证） | ✅ 已验证可用 |
| 标准动作 B 来源 | G1 内置 Mimic 动作库（sdk2 loco API 可获取）+ 教练采集 | 人工关键帧；SEED 数据集（SOMA 生态大规模人体动作，含 G1 动作数据） | ✅ Mimic API 已在 sdk2 仓库确认（2026-08 新增）；SEED 数据集确认存在 |

**核实结论与要点**：

1. **重大发现——GEM-X 端到端管线**：NVlabs/GEM-X 把「单目视频 → SOMA 姿态恢复 → humanoid retarget → Unitree G1 CSV」做成了单仓库一站式流程（`demo_soma.py --retarget --robot unitree_g1`），Apache-2.0 可商用。这直接把 Capture + Retargeting 两层的自研整合量压缩为一个仓库的部署工作，**Demo 首选方案由「WHAM + soma-retargeter 两段式」改为 GEM-X 一体化**，两段式降为备选。
2. **soma-retargeter 输入是 BVH（SOMA 统一比例骨架）**：若不用 GEM-X 而用 WHAM 产出的 SMPL 参数，需要补一个 SMPL → BVH/SOMA 桥接层（GEM-X 路线则无此问题，因其原生输出 SOMA）。
3. **学术支撑全部成立**：NMR（arXiv 2603.22201，南京大学/华为/Horizon，G1 武术与舞蹈任务验证）与 IKMR（arXiv 2509.15443，HKUST(GZ)/ETH/浙大/小米，5000 FPS，G1 真机部署）均为真实论文；二者是「论文级技术储备」，开源代码可用性未确认，不进 Demo 选型，作为第 10 节演进方向的依据。
4. **PoseForge 与我们的 Diff Engine 高度同构**：其板球案例输出的可解释运动学指标（feet gap、elbow angle）与 3.4 节特征集几乎一一对应，可作参考实现；CoachMe 补足的「差值 → 教练指令」语言生成路径，可作语音反馈模块的后期参考。
5. **原「Motion-xperts」名称实为 CoachMe 的项目站点名**（motionxperts.github.io），调研笔记中的项目名与实物对应关系已理清。

## 3. 模块详细设计

### 3.1 Capture Service（感知）

- **实现路径（首选）**：部署 NVlabs/GEM-X，`demo_soma.py --video <相机流> --retarget --robot unitree_g1` 一站式输出 SOMA 姿态 + G1 关节 CSV；备选 WHAM（世界坐标轨迹更稳）+ SMPL→BVH 桥接 + soma-retargeter；
- **输入**：固定机位单目 RGB（或 RGB-D）视频流，用户位于机器人正前方 2–3 m；
- **输出**：逐帧 SOMA/SMPL 参数 + 3D 关键点坐标，统一到机器人坐标系（地面原点 = 机器人站立点）；
- **指标**：≥30fps；姿态估计单帧延迟 ≤100 ms（回放式管道允许离线批处理，实时性压力主要在「二次尝试实时评分」路径；GEM-X 提供 ONNX/TensorRT 加速通道）；
- **实现要点**：
  - 捕捉窗口与机器人静立姿态同步（录制期间 G1 保持安全站姿）；
  - 坐标系对齐以「骨盆高度 + 双脚中点」锚定，消除用户与机器人身高差异的一次项；
  - 训练用机需 NVIDIA GPU（Maxwell 及以上，驱动 545+/CUDA 12），与机器人控制机分离部署。

### 3.2 Retargeting Engine（人体 → G1）

- **输入**：用户轨迹 A 的 SOMA/SMPL 序列；**输出**：G1 23/29 DoF 关节角轨迹（含 torso、双臂、腿部）；
- **实现路径（首选）**：GEM-X 内置 retarget（底层即 soma-retargeter 的 Newton/Warp GPU IK：比例缩放 + 多目标 IK + 关节限位 + 足部稳定）；自研部分收敛为「输出后处理 + 轨迹级校验」；
- **轨迹级校验（安全门，必须全部通过才允许下发）**：
  1. 关节限位：所有帧 q 在 G1 关节软限位内（留 10% 裕度）；
  2. 自碰撞：逐帧碰撞检测（简化胶囊模型）零穿透；
  3. 稳定裕度：质心投影始终在支撑多边形内（演示动作限原地类）；
  4. 速度限幅：关节角速度 ≤ 安全上限（见第 6 节）。
- **兜底**：重定向质量不足时，人工在关键帧编辑器上微调 A 的近似轨迹（Demo 场景接受「近似复刻」）。

### 3.3 Mirror Player（复刻回放，阶段 1）

- 将校验通过的关节轨迹经 **unitree_sdk2 低层接口**下发（详见第 4 节）；
- 回放前 3 秒：G1 以语音/姿态示意「我学一下刚才的你」→ 建立第三人称心理预期；
- 回放速度默认 0.8×（慢放感，强化观察），支持 0.5×/0.8×/1× 三档；
- 回放期间相机继续工作：用户若进入 2 m 安全圈，立即暂停。

### 3.4 Diff Engine（差异量化，阶段 2）

对齐（DTW 时间规整）后，逐帧计算学员轨迹 A 与标准轨迹 B 的差异特征：

| 特征 | 定义 | 反馈形式 |
| --- | --- | --- |
| 重心 Lean | 质心投影相对双脚中点的偏移向量 | 屏幕箭头 + 数值（cm） |
| 关节角差 | 肩/肘/腕/髋/膝相对标准的角度偏差 | 双骨架叠加高亮 |
| 双脚间距 Feet Gap | 双踝水平距离与朝向差 | 脚印示意 + 数值 |
| 节奏 | 动作相位时间差 | 时间轴标注 |

- 输出结构化 JSON（含每特征置信度）；置信度 < 阈值时 UI 降级为「仅总分，不高亮」；
- 每个特征映射 PRD 的量化分（0–100），加权合成总分（Balance/Alignment/Rhythm 三维）。

### 3.5 Motion Morphing（姿态演变，阶段 3 前置）

- 生成 A → B 的渐变轨迹族：q(λ) = blend(A, B, λ)，λ ∈ {0.25, 0.5, 0.75, 1.0}，配合缓动（ease-in-out）；
- 每条渐变轨迹**必须再次通过 3.2 的四项安全校验**（渐变中间态同样不得越界）；
- 产品语义：λ 递增 = 「从你的动作逐步长成正确动作」，可分段慢放；默认演示 λ=0.5 与 λ=1.0 两档；
- 修正姿态 B 的来源：标准库轨迹按**用户身体参数**（柔韧性/臂展）做个性化缩放后的变体，而非原始专家轨迹。

### 3.6 Scoring & Progress

- 逐帧关节角重合度（加权范数）→ 单次总分；两次尝试总分差 = **单次改进幅度**（North Star 指标）；
- 输出 session 报告：三维评分（Balance/Alignment/Rhythm）、逐帧重合度曲线、与历史 session 的进步曲线。

### 3.7 Experience Orchestrator（状态机）

```
IDLE → CAPTURE（录 A）→ REPLAY（G1 复刻）→ DIFF（高亮）
     → MORPH（A→B 渐变）→ RETRY（录 A'，实时评分）→ REPORT → IDLE
```

- 任意状态可被 **e-stop / 安全区入侵** 打断进入 SAFE；
- 屏幕端：双骨架 3D 对比视图 + 差异高亮 + 评分曲线；语音提示全流程引导。

## 4. unitree_sdk2 集成细节

基于 unitree_sdk2（CycloneDDS 消息总线，`dds_wrapper` 的 Channel/ChannelPublisher/ChannelSubscriber，`idl` 数据类型与机器人本体对齐）：

| 用途 | 接口 | 说明 |
| --- | --- | --- |
| 复刻 / 渐变下发 | **低层接口**：关节级 LowCmd（目标 q、dq、kp、kd） | 全关节直控；回放期以**保守增益**（低 kp/kd）+ 速度限幅运行 |
| 站立 / 起立 / 安全姿态 | 高层 `loco_client` | 状态切换与摔倒恢复兜底 |
| 标准动作 B 来源 | G1 Mimic 动作（loco API 可获取内置动作列表） | 冷启动标准库 |
| 状态回读 | 低层 LowState 订阅 | 关节实际位置/速度用于回放自检与评分校准 |
| 网络配置 | ChannelFactory 初始化 DDS 域 | 相机机位与机器人同网段，优先有线直连降低抖动 |

- 开发期用 `unitree_sdk2_python` 快速联调，性能敏感的回放循环用 C++；
- 回放循环控制频率按低层接口实时要求下发（约 500 Hz 量级），轨迹以插值器供给。

## 5. 端到端延迟与性能预算

| 环节 | 预算 | 备注 |
| --- | --- | --- |
| 捕获 + 3D 骨骼（单帧） | ≤100 ms | 录制路径可离线，实时路径（RETRY 评分）需满足 |
| 差异计算 | ≤50 ms | DTW + 特征集，逐帧增量式 |
| 屏幕高亮渲染 | ≤100 ms | 与相机流同步 |
| **实时反馈路径合计** | **≤300 ms** | 用户二次尝试时的评分反馈体感 |
| 复刻回放 | 非实时（离线管线） | 录制→校验→下发，秒级延迟可接受 |

## 6. 安全设计（演示与场馆通用）

| 层 | 措施 |
| --- | --- |
| 物理层 | 演示区围栏；人机距离 ≥2 m（相机实时测距，入侵即暂停）；手持急停 |
| 指令层 | 关节速度限幅（默认 ≤50% 额定）；保守 kp/kd 增益表；关节软限位内 10% 裕度 |

| 数据层 | 骨骼数据本地处理，session 档案匿名化 |

## 9. 风险与降级方案

| 风险 | 影响 | 降级方案 |
| --- | --- | --- |
| 重定向实时性/质量不足 | 复刻失真 | 回放为离线管线；失真时用「近似复刻」+ 人工关键帧微调 |
| 捕捉环境光/服装干扰 | 骨骼抖动 | 服装规范 + 多帧平滑；RETRY 评分降级为总分模式 |
| G1 硬件不可得（排期冲突） | 无法真机演示 | MuJoCo/Isaac 仿真 + 双骨架 3D 渲染合成 Demo（保叙事完整性） |
| 低层接口增益调参不当 | 演示动作僵硬或过冲 | 增益表从极保守起步，按排练逐档上调；固定为已知安全档位 |
| 开源组件许可证/接口变更 | 选型变更 | **已核实（2026-08-27）：全部真实、License 允许商用**；残余风险为 GEM-X/soma-retargeter API 迭代（项目标注 active development），钉住版本 + vendor 快照 |

## 10. 演进方向（Demo 之后）

- **个性化身体模型**：以用户历史轨迹持续拟合身体能力边界（活动度、稳定域），修正建议个性化（对应护城河 2）；
- **RL 全身策略**：参考 H2O 路线，从「轨迹回放」升级为「策略生成」，支持非原地动作与步态；
- **神经重定向升级**：以 NMR（arXiv 2603.22201）与 IKMR（arXiv 2509.15443）为技术储备（均已在 G1 上验证、论文真实），把「优化式 IK 重定向」替换为学习式映射（5000 FPS 量级、噪声免疫、物理可行），支撑实时闭环与大规模个性化轨迹生成；
- **评分体系标准化**：三维评分 → 可跨场馆、跨技能的统一身体技能量表（对应护城河 3）；
- **多技能内容管线**：教练示范采集 → 自动生成标准轨迹 + 差异特征配置的半自动化产线。
