# Mirror Lean 产品需求文档（PRD）

**产品名称**：Mirror Lean

**产品形态**：具身动作学习伙伴

**目标硬件**：Unitree G1 + Camera + External UI / Tablet

**文档版本**：v2.0

**文档状态**：依据《Mirror Lean 最终版产品方案》重构

**一句话定位**：机器人负责把正确动作带到现实空间，AI 负责理解用户与标准动作的差异，并只在真正值得提醒时开口。

---

## 1. 产品概述

Mirror Lean 面向舞蹈等身体动作学习场景。用户上传标准舞蹈视频后，系统解析人体动作并重定向为安全的机器人轨迹；机器人在真实三维空间中完整展示正确动作。用户随后对照平板中的标准视频自主练习，Camera 持续捕捉动作，Mirror Engine 通过 DTW 对齐用户与标准动作阶段并检测差异。

练习过程中，系统仅在差异达到仓库既定阈值、置信度有效且问题持续稳定时，输出一句简短、可执行的语音提醒。用户可以关闭语音，但动作分析与记录仍持续进行。用户主动结束练习后，系统生成包含 Balance、Alignment、Rhythm、Top Differences、动作时间轴和改进建议的完整报告。

产品分工：

| 组成 | 产品角色 | 核心职责 |
| --- | --- | --- |
| Robot | Embodied Reference | 学习并展示正确动作；重放标准片段；慢速展示；保持关键 Pose |
| External UI / Tablet | Learning & Control Center | 上传、标准视频播放、语音开关、练习控制、报告查看、调用机器人示范 |
| Camera | Observer | 实时采集用户动作 |
| Mirror Engine | Motion Intelligence | 3D 姿态、DTW 对齐、差异检测、提醒判断、评分与报告生成 |

## 2. 产品原则与边界

### 2.1 核心原则

1. **机器人永远只展示正确动作**：机器人是标准动作的具身参照，不复刻或表演用户错误动作。
2. **用户掌控练习节奏**：系统不要求固定轮数，不强制 Retry，练习何时结束由用户决定。
3. **Practice 低打扰**：练习中只在必要时给出简短语音动作指令，且语音可关闭。
4. **Review 高信息**：完整差异解释、时间定位、频次与建议统一在练习结束后呈现。
5. **沿用现有技术口径**：Difference 类型、阈值、DTW 对齐和 Balance / Alignment / Rhythm 评分沿用仓库当前代码与 TDD，不在产品层另设冲突标准。

### 2.2 明确不做

- 不复刻用户的错误动作。
- 不展示“用户错误动作 → 正确动作”的 Motion Morphing。
- 不让机器人在用户练习时持续同步跳舞。
- 不强制用户完成固定次数或二次尝试。
- 不在产品层新增一套角度、距离或节奏阈值。
- 不在练习中播报算法术语、角度数值或长篇解释。
- 不进行机器人与用户的身体接触式纠正。

## 3. 目标用户与核心场景

### 3.1 MVP 目标用户

- 希望通过标准视频自学舞蹈的用户。
- 难以仅凭二维视频理解动作幅度、关节关系和重心变化的用户。
- 希望获得客观动作分析，但不希望训练过程被持续打断的用户。

### 3.2 核心任务

> 当我学习一段舞蹈时，我希望先在真实空间中看清正确动作，再按自己的节奏练习，并在明显偏差时得到简短提醒，结束后再系统理解问题和改进方法。

## 4. 目标与成功标准

### 4.1 产品目标

- 让用户能够从屏幕视频与机器人三维示范两个视角理解标准动作。
- 在不打断自主练习节奏的前提下，对关键差异进行及时、可执行的提醒。
- 将实时提醒、差异证据和最终建议串联为可理解、可复盘的学习记录。

### 4.2 MVP 成功指标

| 指标 | 定义 | 验证目标 |
| --- | --- | --- |
| 学习闭环完成率 | 从上传到查看 Session Report 的有效会话比例 | Pilot 阶段建立基线 |
| 练习完成率 | 开始 Practice 后由用户主动结束并生成报告的比例 | Pilot 阶段建立基线 |
| 提醒有效率 | 被用户采纳且后续同类差异减弱的提醒比例 | Pilot 阶段建立基线 |
| 误打扰率 | 因低置信、瞬时差异或冷却失效造成的无效提醒占比 | 持续下降 |
| 报告可理解度 | 用户能否说清主要差异与下一步改法 | 定性测试通过 |
| 示范调用率 | 用户调用“机器人示范这一段”的会话比例 | 用于验证具身参照价值 |

具体数值目标需在首轮可用性测试和 Pilot 数据后设定，PRD 不预设未经验证的商业或提升幅度。

## 5. 核心用户流程

1. 用户上传标准舞蹈视频。
2. 系统完成视频解析、人体姿态提取、标准轨迹生成、Robot Retargeting 与安全校验。
3. UI 显示“Mirror 学会了这个动作”，用户点击“看机器人展示”。
4. 机器人完整展示一次正确动作。
5. 用户进入 Practice，按需开启或关闭“练习中语音提醒”。
6. 用户自由播放、暂停、拖动或重复观看平板中的标准视频，并自主练习。
7. Camera 持续采集；系统完成 3D Pose、DTW 对齐、Difference Detection 与有效性判断。
8. 若满足提醒条件且语音开启，系统输出一条 Primary Difference 的简短提醒；否则只记录。
9. 如用户需要，可暂停并调用“机器人示范这一段”，选择正常速度、慢速或关键 Pose。
10. 用户点击“结束练习”。
11. 系统停止实时反馈并生成 Session Review。
12. 用户查看总结、三维评分、Top Differences、动作时间轴、建议及对应标准片段；必要时再次调用机器人标准示范。

## 6. 功能需求

### 6.1 Upload：标准视频上传与解析

**用户目标**：提交一段希望学习的标准舞蹈视频。

**系统行为**：

- 接收并校验视频文件。
- 执行视频解析与人体姿态提取，生成标准人体轨迹 B。
- 将标准人体轨迹重定向为 G1 机器人轨迹。
- 执行关节范围、自碰撞、稳定性等安全校验。
- 展示处理状态、失败原因与可恢复操作。
- 完成后显示“Mirror 学会了这个动作”及“看机器人展示”按钮。

**验收标准**：

- 未通过安全校验的轨迹不得发送给机器人执行。
- 解析失败时不得进入 Robot Preview，并提供明确重试入口。
- 处理完成后，标准视频与机器人轨迹应关联到同一练习内容。

### 6.2 Robot Preview：完整正确动作展示

**用户目标**：从真实空间和不同角度理解标准动作。

**系统行为**：

- 机器人完整展示经过安全校验的标准动作。
- 平板显示当前展示进度与停止控制。
- 展示结束后提示“现在可以开始自己练习了”。

**验收标准**：

- 展示内容只来自标准动作轨迹，不含用户动作数据。
- 展示期间保留急停与安全距离机制。
- 用户可以安全中止展示。

### 6.3 Practice：自主练习

**界面必须包含**：

- 标准舞蹈视频播放器。
- 播放、暂停、拖动和重复播放能力。
- “练习中语音提醒”ON / OFF 开关。
- “Mirror 正在观察你的动作”状态。
- “机器人示范这一段”入口。
- “结束练习”主操作。

**业务规则**：

- 机器人默认静立，不跟随用户持续跳舞。
- 关闭语音仅关闭播报，不停止采集、差异分析与事件记录。
- 用户可自由决定练习时长和重复次数。
- 用户点击“结束练习”前，系统不得强制进入评分或重试流程。

### 6.4 Motion Capture 与时序对齐

**系统行为**：

- Camera 持续采集用户动作并生成 3D Pose。
- 对姿态特征输出 Confidence。
- 使用 DTW 对齐用户当前动作阶段与标准动作对应阶段。
- 对低置信或不可用片段进行过滤或标记，不据此触发提醒。

**关键约束**：比较对象是“用户当前动作阶段 ↔ 标准动作对应阶段”，不是相同视频时间戳的机械比较。

### 6.5 Difference Detection

沿用仓库现有 Difference 定义：

| Difference | 技术口径 | 产品含义 |
| --- | --- | --- |
| Lean | 质心投影相对双脚中点的偏移向量 | 重心是否偏移 |
| Joint Angle | 肩、肘、腕、髋、膝等与标准动作的角度偏差 | 肢体姿态是否准确 |
| Feet Gap / Orientation | 双踝水平距离与朝向差 | 站位与脚部位置是否准确 |
| Rhythm | 动作相位时间差 | 动作是否提前或滞后 |

**验收标准**：

- Difference 计算发生在 DTW 对齐之后。
- 产品层直接消费 Diff Engine 的差异值、置信度和既定阈值。
- 所有有效 Difference 均可记录到 Session；是否播报不影响记录。

### 6.6 Reminder Engine：实时语音提醒

**触发条件**：以下条件必须同时满足：

1. Difference 超过该特征在 Diff Engine 中的既定阈值。
2. 特征 Confidence 达到有效阈值。
3. Difference 满足持续性 / 稳定性要求，排除单帧波动。
4. 同类问题不处于 Cooldown。
5. 用户已开启练习中语音提醒。

**Primary Difference Selection**：同一时刻存在多个有效问题时，只选择一个最值得打断用户的问题播报。排序可综合差异程度、置信度、持续性和重要性；其他问题继续记录。

**语音文案规则**：

- 格式优先为“身体部位 + 调整方向”。
- 一次只说一个问题。
- 用词简短、自然、可立即执行。
- 禁止使用“你做错了”、算法术语或角度数值。

示例：“左手再抬高一点。”“身体再往左一点。”“双脚再打开一点。”“这里稍微快一点。”

### 6.7 Robot Segment Demo：标准片段示范

**触发方式**：用户主动点击“机器人示范这一段”。

**可选模式**：

- 正常速度。
- 慢速。
- 停在关键 Pose。

**业务规则**：

- 调用前暂停标准视频和用户练习反馈，避免多个动作源同时争夺注意力。
- 示范片段映射到当前标准动作阶段或用户在报告中选择的事件。
- 机器人只播放标准轨迹。

### 6.8 End Practice 与 Session Analysis

用户点击“结束练习”后：

- 停止实时语音反馈。
- 固化本次 Session 的有效动作片段、Difference 事件和 Reminder 事件。
- 调用 Scoring & Progress 生成 Balance、Alignment、Rhythm。
- 聚合整场有效 Difference，形成 Top Differences。
- 生成总体总结、时间轴和改进建议。
- 从 Practice Mode 切换至 Review Mode。

### 6.9 Session Report

报告分为三层：

#### 第一层：本次练习总结

- 一段自然语言总体总结。
- Balance、Alignment、Rhythm 三项结果。
- 总结应指出主要优势和主要差异类别，不做无依据诊断。

#### 第二层：Top Differences

每项至少包含：

- Difference 类型与身体部位。
- 重要程度或出现频次。
- 主要发生时间段。
- 练习中是否播报及当时文案。
- 可执行的改进建议。
- “查看标准片段”入口。
- 适用时提供“机器人示范”入口；Rhythm 优先用视频与时间轴解释，不强制机器人示范。

#### 第三层：动作时间轴

- 展示有效 Difference 事件及 Reminder 标记。
- 点击事件后跳转到标准视频对应位置。
- 显示事件说明、建议及可用的标准示范操作。

### 6.10 实时提醒与报告追溯

每次 Reminder 必须记录：

- Session ID。
- 标准动作阶段与对应时间位置。
- Difference 类型、数值 / 等级与 Confidence。
- 触发时的 Persistence / Cooldown 状态。
- 实际播报文案。
- 播报时间。

报告必须能够说明系统何时、因为什么差异、用什么文案提醒过用户，使实时介入具备事后证据。

## 7. 外接 UI 信息架构

MVP 限定为 5 个核心页面：

1. **Upload**：上传标准舞蹈并查看解析状态。
2. **Robot Preview**：学习完成状态与完整正确动作展示。
3. **Practice**：标准视频、语音开关、观察状态、片段示范、结束练习。
4. **Session Summary**：总体总结与 Balance / Alignment / Rhythm。
5. **Difference Detail**：Top Differences、时间轴、建议、标准片段与 Robot 标准示范。

不扩展为工程调试台；阈值、传感器原始值和机器人底层控制参数不面向普通用户暴露。

## 8. 状态与异常处理

| 状态 / 异常 | 产品行为 |
| --- | --- |
| 视频上传失败 | 保留页面状态，说明失败原因并允许重新上传 |
| 姿态解析失败 | 不生成机器人轨迹，提示更换清晰、全身可见的视频 |
| Robot Retargeting 或安全校验失败 | 禁止播放并提示该动作暂不可展示 |
| Camera 未检测到完整人体 | 暂停有效差异判断，提示用户调整位置；不触发语音纠错 |
| Confidence 过低 | 仅标记为无效 / 低可信片段，不触发提醒 |
| 机器人不可用 | Practice 可继续使用标准视频与动作分析；隐藏或禁用机器人示范入口 |
| 语音关闭 | 继续分析和记录，报告保持完整 |
| 用户中途结束 | 使用已采集的有效片段生成报告；数据不足时明确说明 |
| 急停触发 | 立即停止机器人动作，UI 显示安全状态和恢复指引 |

## 9. 数据与隐私要求

- 默认优先在本地处理原始视频与用户动作数据。
- 用户动作轨迹、Difference 和 Reminder 必须按 Session 隔离。
- 报告所需数据应遵循最小化保存原则。
- 保存或导出可识别的视频前必须获得用户明确授权。
- 用户应能够结束采集，并理解语音关闭不等于分析关闭。

## 10. 非功能需求

### 10.1 安全

- 所有机器人轨迹执行前必须通过安全校验。
- 支持硬件急停、软件停止、安全距离和保守速度限制。
- Robot Preview 与 Segment Demo 都必须允许用户中止。

### 10.2 性能与体验

- 练习状态、语音开关与结束操作需即时响应。
- 动作分析链路应满足近实时提醒需要，具体延迟指标以 TDD 和硬件实测基线为准。
- Reminder 不得因单帧噪声连续触发；Persistence 与 Cooldown 必须可配置、可测试。
- 报告生成期间需展示明确进度，并避免用户误以为数据丢失。

### 10.3 可观测性

- 记录解析、Retargeting、安全校验、Capture、Diff、Reminder 与 Report 各阶段状态。
- 支持按 Session 追踪“检测到差异但未提醒”的原因，例如低置信、未持续、冷却中或语音关闭。

## 11. MVP 优先级

| 模块 | 功能 | 优先级 | P0 验收结果 |
| --- | --- | --- | --- |
| Upload | 标准舞蹈视频上传与解析 | P0 | 可生成关联的标准人体轨迹 |
| Retargeting | 人体轨迹到 G1 轨迹与安全校验 | P0 | 安全通过后才可执行 |
| Robot Preview | 完整正确动作展示 | P0 | 可完整播放、中止，不含用户错误动作 |
| Practice | 标准视频与自主练习控制 | P0 | 支持播放控制、语音开关和主动结束 |
| Capture / DTW | 3D Pose 与动作阶段对齐 | P0 | 可输出有效对齐结果与 Confidence |
| Diff Engine | 四类既有 Difference | P0 | 对齐后输出差异并应用仓库阈值 |
| Reminder | Primary Difference + Persistence + Cooldown | P0 | 只在全部条件满足时播报一句可执行提醒 |
| Session Report | 三项评分、Top Differences、时间轴、建议 | P0 | 提醒可追溯到报告事件 |
| Robot Segment Demo | 正常 / 慢速 / 关键 Pose | P1 | 用户主动调用且只展示标准动作 |
| Progress | 跨 Session 趋势 | P2 | 在 MVP 单次报告稳定后再扩展 |

## 12. 端到端验收场景

### 场景 A：开启语音完成一次练习

1. 用户上传有效标准舞蹈视频，系统完成解析和安全校验。
2. 机器人完整展示正确动作。
3. 用户开启语音并开始自主练习。
4. 单帧或低置信差异不触发提醒。
5. 某个超过既定阈值且持续稳定的高优先级差异触发一条简短语音。
6. 同类问题在 Cooldown 内不重复播报。
7. 用户结束练习后，报告展示该提醒对应的 Difference、时间位置和建议。

### 场景 B：关闭语音完成一次练习

1. 用户关闭语音并练习。
2. 全程不播放动作提醒。
3. 系统继续采集、对齐、检测和记录。
4. 用户结束后仍获得完整评分、Top Differences、时间轴与建议。

### 场景 C：调用机器人片段示范

1. 用户在 Practice 或 Report 中选择一个标准动作片段。
2. 系统暂停冲突中的播放 / 反馈状态。
3. 机器人按正常速度、慢速或关键 Pose 展示标准片段。
4. 全流程不加载或复现用户错误动作。

## 13. 风险与应对

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 机器人动作安全 | 高 | Retargeting 后强制安全校验、距离围栏、保守速度、急停冗余 |
| 姿态遮挡或误检导致误提醒 | 高 | Confidence Filter、Persistence、Cooldown、低置信不提醒 |
| 提醒过多打断学习 | 高 | 一次只播报 Primary Difference；语音可关闭；监控误打扰率 |
| DTW 错配动作阶段 | 中 | 记录对齐置信度；低可信对齐不触发提醒并在报告中降权 |
| 报告信息过载 | 中 | 默认只展示 Top Differences，原始事件收纳在时间轴详情 |
| 机器人价值被平板替代 | 中 | 强化首次完整三维示范与按需片段 / 关键 Pose 展示，不让机器人沦为实时播报载体 |
| 用户误解语音关闭 | 中 | 开关旁明确提示“关闭提醒后仍会分析，并在结束后生成报告” |

## 14. 版本路线图

| 阶段 | 核心交付 | 退出标准 |
| --- | --- | --- |

## 15. 技术口径与依赖

本 PRD 的实现依赖仓库现有技术分层：Capture Service、Retargeting Engine、Diff Engine、Scoring & Progress、Experience Orchestrator。以下定义以仓库代码和 `docs/TDD.md` 为准：

- 3D Pose 与特征 Confidence。
- DTW 动作时序对齐。
- Lean / Joint Angle / Feet Gap & Orientation / Rhythm。
- 各 Difference 的既定阈值。
- Balance / Alignment / Rhythm 评分结构。
- Robot 标准轨迹播放与安全控制。

若 PRD 描述与上述技术定义出现冲突，应先校准产品表达，不得在体验层复制或重定义底层算法口径。

---

**产品价值主张**：把标准动作从屏幕带进真实空间，把动作反馈从持续纠错变成适时介入。

**产品化表达**：看视频学，向机器人理解；练习时少打扰，结束后把差异讲清楚。
