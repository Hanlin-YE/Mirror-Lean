Mirror Lean 最终版产品方案

机器人仅展示正确动作 · 阈值触发语音提醒 · 结束后完整动作差异报告

方案原则：机器人永远只展示正确动作；用户自主练习；练习过程中仅在动作差异达到既定临界条件时进行简短语音提醒，且提醒可关闭；用户主动结束后再输出完整动作差异分析与改进建议。Difference 类型、DTW 对齐及 Balance / Alignment / Rhythm 评分结构直接沿用仓库现有技术定义。

# 1. 产品定位

Mirror Lean 是一个具身动作学习伙伴。用户上传标准舞蹈视频后，机器人学习并在真实空间中展示正确动作；用户对照外接 UI 自主练习，系统持续观察用户动作，仅当动作差异达到既定临界条件时进行简短语音提醒；练习结束后输出完整动作差异分析与改进建议。

一句话定位：机器人负责把正确动作带到现实空间，AI 负责看懂你与标准动作的差异，并在真正值得提醒时开口。

- Robot = 正确动作的具身参照

- AI = 动作差异理解与提醒判断

- 外接 UI = 学习、控制与复盘中心

# 2. 产品形态

| 组成 | 产品角色 | 核心职责 |
| --- | --- | --- |
| Robot | Embodied Reference | 学习并展示正确动作、局部标准动作重放、慢速展示、关键 Pose 保持 |
| External UI / Tablet | Learning & Control Center | 上传视频、播放标准视频、语音提醒开关、练习控制、报告查看、调用机器人示范 |
| Camera | Observer | 实时采集用户动作 |
| Mirror Engine | Motion Intelligence | 3D 姿态、时序对齐、Difference Detection、提醒判断、评分与报告生成 |

仓库技术层已经具备 Capture Service、Retargeting Engine、Diff Engine、Scoring & Progress、Experience Orchestrator 等分层，因此新的产品形态不需要推翻底层，只需要重组体验层。

# 4. 流程具体内容及功能

# 4.1上传并让机器人学习

用户上传一个想学习的标准舞蹈视频。系统完成：视频解析 → 人体姿态提取 → 标准轨迹 B → Robot Retargeting → 安全校验。

完成后 UI 显示：“Mirror 学会了这个动作”。并提供按钮：[ 看机器人展示 ]。

# 4.2 Robot Preview：机器人先完整跳一遍

机器人完整展示标准动作。此时机器人只有一个身份：Correct Motion Reference。

机器人不展示用户错误动作，不做“你的动作 → 正确动作”的肢体差异演示。

平板中的真人视频负责动作风格和细节，机器人提供真实三维空间中的身体轨迹和关节关系。用户可以从不同角度观察。

展示结束后进入：“现在可以开始自己练习了。”

# 4.4 实时 Difference Detection

实时动作差异检测直接沿用仓库已有定义，不再创造新的动作指标。所有比较在动作时序经过 DTW 对齐后进行。

| 差异类型 | 仓库定义 | 产品含义 |
| --- | --- | --- |
| Lean | 质心投影相对双脚中点的偏移向量 | 重心是否偏移 |
| Joint Angle | 肩/肘/腕/髋/膝与标准动作角度偏差 | 肢体姿态是否准确 |
| Feet Gap / Orientation | 双踝水平距离与朝向差 | 站位/脚部位置 |
| Rhythm | 动作相位时间差 | 是否提前/滞后 |

关键原则：不是“标准视频第 10 秒 vs 用户第 10 秒”，而是“用户当前动作阶段 ↔ 标准动作对应阶段”。

# 4.5 提醒机制

## 练习中语音提醒

ON：当动作差异达到系统设定的提醒条件时，Mirror 会进行简短语音提醒。

OFF：Mirror 不在练习过程中打断用户，但仍持续观察并记录所有有效动作差异，结束后统一分析。

关闭提醒 ≠ 关闭动作分析。

## 提醒临界值：直接沿用 Diff Engine 的阈值体系

正式规则：Reminder Engine 直接消费 Diff Engine 输出的差异值、特征置信度和系统既定阈值。产品层不再额外创造一套 10° / 20° 等独立标准。

Diff Engine
    ↓
差异值超过该特征既定阈值？
    ↓
Confidence 是否达到有效阈值？
    ↓
当前 Difference 是否足够稳定？
    ↓
是否刚提醒过同类问题？
    ↓
语音提醒是否开启？
    ↓
YES
    ↓
生成一句可执行动作提醒

即：“什么叫差异够大”由现有 Diff Engine 定义；产品层不另设一套矛盾标准。

## 为什么仍然需要持续性判断和 Cooldown

即使 Difference 超过既定阈值，也不能单帧触发语音。提醒调度必须继续考虑差异是否连续/稳定、同类问题是否刚提醒过，以及用户是否开启语音提醒。

这些 Persistence / Cooldown 规则属于交互调度层，不重新定义 Diff。

## 语音提醒标准

所有语音坚持“身体部位 + 调整方向”，避免解释算法。

- “左手再抬高一点。”

- “身体再往左一点。”

- “双脚再打开一点。”

- “这里稍微快一点。”

避免使用“你做错了”或播报角度数值。练习中的语音目标只有一个：Actionable，用户听完立刻知道怎么调整。

## 同一时刻多个差异：Primary Difference Selection

Diff Engine 可以同时发现多个问题，但语音一次只能输出一个最值得打断用户的问题。

Primary Difference 可以基于：差异程度 × 置信度 × 持续性 × 重要性排序。

左手高度      HIGH
重心偏右      MEDIUM
右膝角度      LOW
节奏          LOW

→ 只输出：
“左手再抬高一点。”

其他差异继续记录，统一进入练习结束后的分析。

# 4.6 机器人什么时候再次出现

用户自主练习过程中，机器人默认不动。平板始终提供“机器人示范这一段”。

如果用户听到语音提醒但不理解，可以暂停视频并调用机器人重新展示当前标准动作片段。

- 正常速度

- 慢速

- 停在关键 Pose

机器人始终只展示正确动作。

# 4.7 用户点击结束后：从 Practice Mode 切换到 Review Mode

用户点击“结束练习”后停止实时反馈，进入 Session Review。

体验原则：Practice = Low Interruption；Review = High Information。

# 4.8 最终动作差异报告

## 第一层：本次练习总结

示例：“本次动作整体节奏较稳定，主要差异集中在上肢动作幅度和重心转换。”

报告展示 Balance / Alignment / Rhythm 三个维度，沿用仓库现有 Scoring & Progress 体系。

## 第二层：核心动作差异

整场 Session 的有效 Difference 按重要程度聚合，优先展示 Top Differences，而不是把所有原始差异平铺。

示例 01｜左臂动作幅度：出现频繁；主要时间 00:12–00:18；过程中语音提醒“左手再抬高一点”；建议“抬臂阶段可以更加充分，同时注意肩部保持自然”；支持 [ 查看标准片段 ] 与 [ 机器人示范 ]。

示例 02｜重心转换：主要时间 00:21–00:25；建议“转身过程中可以更早完成重心转移，让后续动作衔接更自然”；支持查看标准动作。

示例 03｜节奏：主要出现于第二个八拍；建议“这一段动作启动稍慢，可以提前跟随音乐重拍进入动作”。节奏问题以视频和时间轴解释为主，不强行调用机器人。

## 第三层：动作时间轴

00:00 ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 00:31

        ▲         ▲ ▲            ▲
      左臂       重心            节奏
       🔊          │
      提醒

用户点击某个事件后，平板跳到标准视频对应位置，并显示该差异的说明；可继续播放标准片段或调用机器人示范。

# 4.9把“实时提醒”和“最终报告”打通

报告需要记录系统训练过程中为什么提醒过用户。

| 时刻 | Difference | Mirror 提醒 |
| --- | --- | --- |
| 00:08 | 左臂动作幅度 | “左手再抬高一点” |
| 00:16 | 重心偏移 | “身体往左一点” |
| 00:24 | 节奏滞后 | “这里快一点” |

这样每一次实时提醒都有事后证据，用户能理解 Mirror 为什么当时开口。

# 7. 最终产品边界

1. 机器人永远只展示正确动作：不复刻用户错误动作，不做错误姿态展示，不做 A→B 错误纠正 Morph。

1. 用户自主练习：Mirror 不要求固定次数、不强制重试、不替用户控制练习节奏。

1. 实时阶段只做必要的简短语音提醒：且用户可以完全关闭。

1. 完整分析留到练习结束以后：实时只给动作指令，结束后再解释为什么、什么时候、出现多少次、对应哪个动作、建议怎么改。

# 8. 产品差异化

这版并不是“摄像头 + 平板 + 一个会说话的机器人”。

真正的产品分工是：Camera 看见用户，AI 理解差异，Tablet 帮用户自主学习，Robot 把标准动作变成一个真实存在的三维身体参照。

普通姿态识别产品的路径通常是：视频 → 看 → 模仿 → 屏幕告诉你错哪。

Mirror Lean 的路径是：视频 → Robot 学会并实体化标准动作 → 用户自主学习 → AI 安静观察 → 真正明显时才提醒 → 结束后系统性复盘 → 随时调用机器人重新查看正确动作。

最终价值主张：把标准动作从屏幕带进真实空间，把动作反馈从持续纠错变成适时介入。

产品化表达：看视频学，向机器人理解；练习时少打扰，结束后把差异讲清楚。
